# 项目勘察报告

## 1. 当前项目结构

- `shared/`：Kotlin Multiplatform 共享模块，当前包含 `RouterPage`、`ImageAdapterBenchmarks`、`BasePager`、桥接模块和工具类。
- `androidApp/`：Android 宿主，包含 `KuiklyRenderActivity`、Application、渲染适配器、路由适配器和原生模块。
- `iosApp/`：iOS 宿主和 Kuikly View Controller/Router Handler 预留代码。
- `ohosApp/`：OpenHarmony 宿主、ETS 适配器和测试代码。
- `static_server/`：由 `package.json` 脚本驱动的静态服务器目录（当前文件清单中未发现完整源码）。
- `buildSrc/`：构建常量和 Kuikly 插件坐标。
- 根目录 Gradle/Kotlin 配置：控制模块、仓库和版本。

根 `settings.gradle.kts` 声明了 `:androidApp`、`:shared`、`:h5App`、`:miniApp`，但当前目录清单未发现对应 `h5App`、`miniApp` 目录，后续构建需确认是否为模板遗留配置。

## 2. 技术栈和版本

- Gradle Wrapper：8.5（`gradle/wrapper/gradle-wrapper.properties`）。
- Kotlin：2.1.21；OpenHarmony 专用构建脚本使用 2.0.21-KBA-010。
- Android Gradle Plugin：根脚本和 Android 模块均配置 7.4.2；版本目录中的 `agp=9.3.0` 当前未被根插件声明实际采用。
- Kuikly：2.7.0-Kotlin 2.1.21；核心、注解、KSP、Android Renderer 和 Gradle Plugin 均由 `buildSrc` 统一生成坐标。
- JDK：项目显式未声明 toolchain；源码编译目标 Java/Kotlin 1.8，当前环境为 JDK 17。
- Android SDK：compileSdk 34；App minSdk 23、targetSdk 30；shared minSdk 21、targetSdk 30。
- Android 依赖：shared 模块、RecyclerView 1.2.1、AppCompat 1.3.1、Picasso 2.71828、Core KTX 1.6.0、DynamicAnimation 1.0.0、Glide 4.12.0 及其 compiler。
- JS/静态服务器依赖：Koa、koa-router、koa-static 等，主要服务于静态产物承载。

## 4. Kuikly 核心入口

- 页面入口由 `@Page` 注解注册，当前页面为 `RouterPage`（`@Page("router")`）和 `ImageAdapterBenchmarks`。
- Android 启动入口为 `KuiklyRenderActivity`，默认打开 `router`，通过 `KuiklyRenderViewBaseDelegator.onAttach` 创建 Kuikly 页面。
- Android 通过 `registerExternalModule` 注册桥接、分享等原生模块，通过 `KuiklyRenderAdapterManager` 注册图片、日志、路由、线程等适配器。
- shared 层 `BasePager` 统一处理夜间模式和外部 `BridgeModule`。

## 5. 推荐页面结构

- `StockHomePage`：行情首页和股票列表。
- `StockDetailPage`：股票基础行情、走势区域和 AI 分析。
- `StockChatPage`：聊天记录、输入框、发送操作和 AI 结构化回复。
- 可选 `MarketOverviewPage`：市场概览；第一版可并入行情首页。

## 6. 推荐数据模型

- `StockInfo`：名称、代码、价格、涨跌额、涨跌幅。
- `StockDetail`：最高价、最低价、成交量、成交额、时间序列和更新时间。
- `AiAnalysis`：趋势、建议、风险、信号、摘要。
- `ChatMessage`：发送方、文本、时间、消息类型和结构化载荷。
- `StockCardData`/`IndexCardData`：聊天回复中的可点击卡片。

第一版建议使用 `MockStockRepository`、`MockAiRepository`，保留后续替换真实接口的边界。

## 7. 推荐状态管理方式

沿用 Kuikly 的 `observable` 响应式属性和 Pager 生命周期：页面级状态放在对应 Pager，列表、加载状态、输入文本、消息集合和错误状态使用可观察字段。共享数据读取逻辑放入 Repository，避免把数据处理塞进 `body()`。

## 8. 推荐导航方案

继续使用 `RouterModule.openPage`/`closePage`。统一页面名和参数，例如 `stock_home`、`stock_detail`、`stock_chat`，详情页通过 `code` 或 `symbol` 参数接收股票标识。Task 1 列表点击和 Task 2 卡片点击均进入同一个 `StockDetailPage`。

## 9. Task 1 实现计划

1. 准备股票数据模型和本地行情数据。
2. 实现可滚动行情列表和涨跌样式。
3. 实现详情页指标网格和简化走势展示。
4. 实现 AI 分析卡片，覆盖趋势、操作提示、风险和总结。
5. 验证列表到详情的跨端路由。

## 10. Task 2 实现计划

1. 准备聊天消息模型和本地问答规则。
2. 实现聊天列表、输入框、发送按钮和滚动定位。
3. 实现 Markdown 文本的基础渲染策略。
4. 实现股票/指数结构化卡片和详情按钮。
5. 打通聊天结果到 `StockDetailPage` 的跳转。

## 11. 两个 Task 的代码复用方案

共享股票模型、Mock Repository、详情页、导航栏、行情指标组件、涨跌颜色规则、走势组件和 AI 分析卡片。Task 2 的股票卡片复用 Task 1 的摘要卡片和详情路由；两者共用加载、空状态和错误提示样式。页面自身只保留业务编排，避免复制行情字段和跳转逻辑。
