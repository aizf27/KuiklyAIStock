# 9.8 项目优化计划

## 1. 目的与边界

本计划以 `docs/UI与架构审查.md` 为问题输入，并以当前工作区代码、`docs/TASKS.md`、`DESIGN.md` 为事实基线。目标是在开始 Task 2 前，解决 Task 1 已确认的导航、跨页状态、视觉一致性和数据边界问题，同时保留 Kuikly `commonMain` 复用边界。

本轮不包含真实行情或 AI 服务、搜索/提醒/账号、周 K/月 K、复杂图表交互，也不升级 Kotlin、Gradle、AGP、Kuikly 或引入 Compose。

当前工作区已有未提交的 Task 1 改动。本计划实施时必须在该基线之上增量修改，不重置、不覆盖、不混入无关格式化。

## 2. 已确认结论

| 优先级 | 问题 | 当前证据 | 处理决定 |
| --- | --- | --- | --- |
| P0 | Tab 切换不断入栈 | `StockAppShell.openStockPage()` 直接调用 `RouterModule.openPage()`；Android 路由适配器每次启动新的 `KuiklyRenderActivity` | 改为根 Tab 替换语义，并做返回栈验收 |
| P0 | 自选跨页刷新不可靠 | `WatchlistStore` 为非响应式 `linkedSetOf`；首页和详情各维护 `favoriteVersion` | 收敛到一个可订阅状态源，移除页面各自的失效计数 |
| P0 | 顶部栏不符合设计规范 | `RouterNavBar` 位于模板 `RouterPage.kt`，标题使用青紫渐变 | 抽为股票共享组件，使用白底、纯色文字和统一返回样式 |
| P0 | 详情标题重复 | 导航栏和身份区都显示股票名 | 导航栏仅承担返回与页面语义，身份区保留唯一主标题 |
| P1 | Loading 不能被观察到 | Repository 同步返回，页面同一调用栈内从 `loading=true` 变为 `false` | 建立异步加载边界，Mock 支持可控延迟、成功和失败 |
| P1 | 模板与业务职责混杂 | 业务复用的 `RouterNavBar` 放在模板路由页；`BridgeModule` 大量未使用能力 | 先抽离业务组件，再做可验证的模板隔离；不直接删除宿主相关代码 |
| P1 | 数据/测试契约不闭合 | 死字段、样本成交额口径、格式化边界与自选逻辑缺测试 | 收敛模型语义并补纯函数、状态和数据一致性测试 |

## 3. 实施顺序

### 阶段 0：建立可回归基线

1. 记录当前分支、未提交文件和已知构建限制，不修改既有未提交改动。
2. 在目标设备上手工复现两条基线：连续切换“行情/自选/AI 解读”后的返回顺序；详情页修改自选后返回首页的星标和筛选列表状态。
3. 先确认 Kuikly 的页面关闭时机、`RouterModule` 的打开/关闭顺序，以及 `observable` 在共享对象中的订阅行为。当前源码只能确认 `RouterModule.openPage()` 会启动新页面，不能假定 `closeSamePage` 对该调用生效。
4. 形成一页验证记录：复现步骤、实际栈行为、选定方案和不选其他方案的原因。若框架不支持安全的“打开后关闭当前页”，再评估单页 Tab 容器，不在未验证前改路由。

验收：上述两条问题均可稳定复现，且路由/响应式方案有最小原型证据。

### 阶段 1：修复根 Tab 导航与自选状态

1. 在 `StockAppShell` 中区分“进入详情”和“切换根 Tab”两种导航意图，禁止 Tab 点击复用详情的普通 push 路由。
2. 实现根 Tab 的替换语义：重复点击当前 Tab 不导航；从行情/自选切到 AI、或从 AI 回到行情/自选后，返回键不应回到前一个 Tab。详情页仍按正常 push 打开，返回应回到来源根 Tab。
3. 将 `WatchlistStore` 重构为唯一状态入口：收藏集合、读取、切换、筛选和变更通知均在该入口；页面只读取订阅状态，不再自行维护 `favoriteVersion`。
4. 为页面销毁/返回场景补充取消订阅或等价生命周期清理，避免页面实例残留导致重复刷新。
5. 在收藏切换、根 Tab 跳转、详情跳转与返回分支保留简短 `Log.i`/`Log.e`，日志只记录代码、目标页和结果，不记录无关数据。

验收：从“行情 -> AI 解读 -> 自选 -> 行情”连续切换 10 次，返回键不会逐层回放 Tab 历史；任一详情页添加/取消自选后返回首页，星标与自选列表立即一致。

### 阶段 2：收口导航与核心视觉

1. 新建股票共享导航组件文件，迁出 `RouterNavBar`；股票页面不再依赖 `RouterPage.kt` 中的模板 UI。
2. 顶部栏统一为 `surface` 背景、`primaryText` 标题和与品牌色一致的返回控件，去掉青紫渐变。首页和 AI 页保留无返回模式；详情页保留返回模式。
3. 详情页只在正文身份区显示股票名称与代码，导航栏显示固定的“股票详情”或仅保留返回区域，避免双主标题。
4. 底部栏增加 1dp 顶部分隔线，替换 `▦`、`★`、`AI` 的混用占位表现。图标方案优先采用当前 Kuikly 可稳定渲染的统一图标资源；若框架无跨端图标能力，则使用同一套简洁文本符号并保证语义不与列表收藏星标冲突。
5. 修正 `formatStockVolume`、`formatStockTurnover` 的整数显示，杜绝 `1832.0万` 一类结果；行情数值继续保留正负号和右对齐。

验收：360x800 下顶部、正文和底部栏无渐变残留、无重复股票主标题、无裁切；成交量/成交额整数不显示多余 `.0`；底部栏的三个入口可一眼区分且有分隔线。

### 阶段 3：建立可替换的异步 Repository 边界

1. 不直接添加协程依赖。基于现有 Kuikly 定时/回调能力，先选定与 `commonMain` 兼容的回调式加载契约；只有现有依赖已提供可靠 scope 时才评估 `suspend`。
2. 将首页、详情和 AI 页所需数据按页面加载单元封装为成功/失败结果，页面保留上次成功数据，避免刷新失败后清空内容。
3. Mock Repository 支持测试可控的延迟、空数据和失败分支；默认演示延迟应短且可关闭，避免影响普通浏览。
4. 页面在请求开始、成功、失败时更新 observable 状态，并在页面已销毁或新请求覆盖旧请求时忽略过期回调。
5. 不在 `body()` 组装数据或触发请求；日志覆盖请求开始、成功、失败和过期结果丢弃。

验收：加载骨架至少能在可控延迟下稳定可见；首页、详情、AI 页均能展示成功、空/失败和重试；替换 Mock 为真实实现时只改 Repository 注入层，不改页面布局结构。

### 阶段 4：模型、图表与组件契约收口

1. 决定 `AiAnalysis.signalInterpretation`：在详情与 AI 卡片中以“信号解读”展示，或从模型与 Mock 中删除；不保留无使用字段。
2. 明确首页成交额为“样本成交额”，或新增独立的市场级 Mock 字段；不得将五只样本之和标为全市场成交额。
3. 统一路由定位符。当前 `symbol` 等同于 `code`，本阶段选择其一：删除别名并全链路只传 `code`，或新增真实市场 `symbol` 并补映射和测试。Task 2 必须沿用同一选择。
4. 为 `TrendPoint` 补足周期/时间语义，移除单点数据绘制到固定 `66f` 的行为；单点应绘制在按价格计算的位置。补充昨收基准线、最高/最低参考信息的可读标注。
5. 复核详情页的“卡片还是分隔线”取向：市场摘要、图表、AI 汇总允许 8dp 容器；价格、关键行情等普通区块改轻量分组与分隔线，或同步修订 `DESIGN.md`。实现和规范必须选定同一结论。
6. 组件按 `common/`、`home/`、`detail/`、`ai/` 组织或采用等价命名规则。仅在移动涉及文件时做最小迁移，不为目录整齐进行无关重构。

验收：模型没有无展示、无注释说明的死字段；首页数据文案符合数据来源；走势图在空、单点、多点、极值相同和两种周期下均无硬编码位置异常。

### 阶段 5：模板隔离、测试与文档同步

1. 先完成阶段 2 的导航组件迁移，再检查 `RouterPage` 是否仍被入口、调试或基准测试引用。未被引用的模板调试页从正式路由隔离；无法安全删除的宿主代码保留并说明原因。
2. 对 `BridgeModule` 逐项检索 commonMain 和宿主调用。仅在 Android、JS 及注册链路均确认无引用后移除无关桥方法；`log`、导航和页面关闭链路不能凭“页面未直接调用”删除。
3. 补充单元测试：价格/百分比/成交量/成交额格式化边界、涨跌/平盘颜色、自选切换与筛选、Mock 行情的价格差和百分比一致性、未知代码处理。
4. 更新 `docs/TASKS.md`、`docs/PROJECT_PROGRESS.md`、`docs/UI优化建议.md`、`DESIGN.md`：已实现、待实现、明确延期三类分开记录；删除已完成仍标待办的条目。
5. 本计划完成后补充最终优化记录，列出实际完成项、未做项、验证命令和环境阻塞原因。

验收：正式股票页面不依赖模板导航栏；测试覆盖新增的纯函数与状态分支；进度和设计文档不再把建议项表述为已完成实现。

## 4. 验证矩阵

| 类别 | 必测场景 | 通过标准 |
| --- | --- | --- |
| 路由 | 连续切 Tab、重复点当前 Tab、详情进入/返回、错误页返回 | Tab 无栈累积；详情只返回来源根 Tab；无白屏 |
| 自选 | 首页添加、详情取消、返回自选页、空态“去行情添加” | 三处状态立即一致，无需重建页面 |
| 数据状态 | 首次加载、延迟、空数据、失败、重试、旧请求晚到 | 骨架/错误/重试可见；旧数据不被过期回调覆盖 |
| UI | 360x800、长名称、长数值、5 条以上列表、详情单点图 | 不重叠、不裁切，数值对齐稳定，设计 Token 一致 |
| 自动化 | `:shared:compileKotlinJs`、相关 Kotlin 测试 | 编译和可执行测试通过；若仍受 Kuikly IR 或 D8 环境阻塞，记录完整错误与已完成的替代验证 |
| 宿主 | Android 真实设备或模拟器 | 核心链路、返回栈和视觉验收通过；构建失败不得伪报为功能通过 |

## 5. 提交与风险控制

每阶段应保持原子提交，建议提交名依次为：

1. `优化股票根Tab导航与自选状态同步`
2. `统一股票导航栏与核心视觉细节`
3. `建立股票Repository异步加载边界`
4. `收口股票模型图表与数据语义`
5. `清理股票模板依赖并同步测试文档`

实际实施前先确认当前未提交改动的归属；未经确认不将它们纳入上述提交。每阶段完成后先执行对应验证、检查 `git diff --check` 和无关变更，再决定是否提交。

## 6. 审查结论

建议按本计划执行，不把“模板清理”和“异步化”抢在路由及状态正确性之前。最先需要拍板的是根 Tab 的替换实现：必须通过阶段 0 的 Kuikly 原型验证后再进入正式改造。其余项目可按阶段顺序独立验收，完成阶段 1 与阶段 2 后即可获得明显的可用性和视觉收益，再开始 Task 2。
