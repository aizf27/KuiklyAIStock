# 腾讯行情真实数据源接入计划

> 状态：待审核，确认后实施。  
> 日期：2026-09-11。

## 1. 目标与范围

将首页行情、自选列表和个股详情从本地 Mock 行情切换为 `qt.gtimg.cn` 行情快照，同时保持现有收藏、持仓、图表、AI 分析和交易流程不被破坏。

本期范围：

- 首页配置股票池的最新报价；
- 上证指数、深证成指、创业板指行情；
- 个股详情的现价、昨收、今开、最高、最低、成交量、成交额；
- 请求失败、返回异常、部分股票缺失、缓存和过期请求保护；
- Android 可运行，并尽量全部放在 `commonMain`，为 iOS、鸿蒙复用 Kuikly `NetworkModule`。

本期不把单次行情快照伪造成分时或日 K。`qt.gtimg.cn` 当前接入只负责快照；真实走势图需要后续确认独立的分时/K 线接口。

## 2. 核心方案

采用“共享 Repository + Kuikly NetworkModule Transport + Mock 显式降级”的结构：

```text
StockHomePage / StockDetailPage
        ↓ lazy 注入
TencentStockRepository
        ↓
TencentQuoteTransport
        ↓
NetworkModule.requestGetBinary
        ↓
GBK 解码 → 文本解析 → 校验 → StockQuote / StockDetail
```

关键原则：

- Pager 内通过 `acquireModule<NetworkModule>(NetworkModule.MODULE_NAME)` 获取模块，并使用 `lazy` 缓存；
- 使用 `requestGetBinary` 获取 `ByteArray`，成功后按 GBK 解码；
- Repository 不直接依赖 Android API，也不新增宿主 Bridge 或网络库；
- 网络层、解码层、解析层分离，单元测试不发真实请求；
- 真实请求失败时优先展示最近一次真实缓存；没有缓存则显示错误和重试，不静默伪装成实时 Mock。

## 3. 共享层改动

### 3.1 Transport

新增 `QuoteTransport` 接口和 `KuiklyQuoteTransport` 实现：

- 输入：完整 URL、超时；
- 输出：二进制正文、HTTP 状态码、错误信息；
- 回调先判断 `success`，成功后才能读取 `data`；
- 失败分类为网络错误、超时、HTTP 错误、解码错误、格式错误；
- 行情请求超时建议设为 10 秒，不沿用默认 30 秒；
- 日志只记录请求类型、股票数量、状态、耗时和错误类别，不记录完整返回正文。

Repository 内将 Transport 回调适配到现有 `suspend` 接口，继续兼容 `StockRepository.loadHome/loadDetail/loadAi`。

### 3.2 GBK 解码

成功响应统一经过 `TencentQuoteDecoder`：

1. `ByteArray` 按 GBK 解码；
2. 去除空行和首尾空白；
3. 按每条 `v_xxx="...";` 记录拆分；
4. 再按 `~` 拆分字段。

优先在 `commonMain` 使用 Kuikly 当前可编译的 GBK 解码方式。若后续 iOS/鸿蒙目标不支持同一 Charset API，只替换 `QuoteTextDecoder` 的平台实现，不改 Repository 和页面。

### 3.3 解析器

新增纯 Kotlin `TencentQuoteParser`，禁止在 UI 中按下标取字段。

- 用具名常量集中维护字段位置；
- 校验变量名、返回股票代码和请求代码一致；
- 数字使用安全转换，拒绝 `NaN`、无穷值和负价格；
- 校验昨收大于 0、最高价不低于最低价；
- 成交量、成交额的单位转换集中处理；
- 涨跌额和涨跌幅优先使用接口值，缺失时才由现价和昨收计算；
- 时间统一转换为页面当前使用的 `yyyy-MM-dd HH:mm`；
- 单条异常不拖垮整个批量响应，但必须记录缺失代码。

字段下标和单位不凭经验散落编码。实施前先保存一组真实返回为脱敏测试 Fixture，再锁定名称、代码、现价、昨收、今开、最高、最低、成交量、成交额、更新时间对应位置。

## 4. 股票代码与批量请求

新增统一的 `TencentSymbolMapper`：

- 沪市股票转为 `sh + 六位代码`；
- 深市/创业板转为 `sz + 六位代码`；
- 指数固定使用 `sh000001`、`sz399001`、`sz399006`；
- 不支持或无法判断市场的代码在发请求前直接返回参数错误。

首页将当前配置股票池和三个指数合并为一次批量请求，避免逐行请求。详情页只请求当前股票。搜索仍然是对已配置并已加载的股票池做本地过滤，本期不新增股票搜索接口。

## 5. Repository 与数据模型

新增 `TencentStockRepository`，保留 `MockStockRepository` 供测试和显式演示模式使用。

建议新增行情元信息：

- `MarketDataSource.REMOTE / CACHE / MOCK`；
- 数据提供方；
- 请求完成时间；
- 行情时间；
- 是否过期；
- 批量响应中缺失的股票代码。

元信息放在 `StockHomeData`、`StockDetailData` 层，避免每个报价对象重复保存。

### 首页

- `quotes`：解析成功的股票报价；
- `indices`：从同一批请求解析三个指数；
- 涨、跌、平数量仅表示“当前配置股票样本”，不宣传为全市场统计；
- 样本成交额可由有效股票求和；
- 当前接口无法可靠提供的净流入字段不再伪造，模型改为可空，UI 显示“暂无数据”或隐藏；
- 部分股票失败时展示有效数据，并给出轻量“部分行情未更新”提示。

### 详情

- 直接映射现价、今开、昨收、最高、最低、成交量、成交额；
- 目标股票缺失、停牌导致核心价格不可用或字段不合法时返回明确失败，不拼接 Mock 详情；
- `intradayTrend`、`dailyTrend` 在没有真实时序数据时返回空列表；
- 图表区域显示“暂无真实走势数据”，不得继续展示未标识的 Mock 曲线。

## 6. 缓存、刷新与降级

增加进程内行情缓存：

- Key：标准化股票代码；
- Value：最后一次通过校验的真实报价及行情时间；
- 首页和详情共用缓存；
- 缓存命中必须标记 `CACHE` 并显示原始行情时间；
- 新响应时间早于缓存时间时丢弃，防止旧行情回滚。

首版刷新策略：

- 首页进入时请求一次；页面存活且处于行情 Tab 时每 30 秒刷新；
- 详情页进入时请求一次，每 15 秒刷新；
- 页面销毁后停止定时任务并使请求序号失效；
- 非交易时段降低刷新频率或停止轮询；
- 重试按钮立即发起一次新请求；
- 同一页面同一时刻只允许一个同类请求在途。

降级顺序：

1. 新的远程真实行情；
2. 最近一次真实缓存，并明确标记“缓存行情”；
3. 无缓存时显示失败和重试；
4. Mock 仅用于显式演示/开发开关，不作为无提示的自动兜底。

## 7. 页面状态与 UI

复用现有 `observable`、`StockRequestTracker` 和加载/错误组件，不引入 Compose 或 ViewModel。

- 首页增加行情来源、更新时间和部分失败提示；
- 自选和持仓继续从首页同一份报价映射，不单独重复请求；
- 详情页刷新报价时不重置收藏、持仓、交易弹窗和图表周期；
- 快速切股、重试和页面销毁后，旧请求不得覆盖新页面；
- 行情涨跌继续同时使用颜色和正负号；
- 原“行情为演示数据”文案改为按来源动态展示：真实、缓存或演示；
- 缓存和远程结果都显示接口行情时间，而不是仅显示手机当前时间。

## 8. 与 AI 分析的衔接

详情行情成功后再触发当前 `AiAnalysisRepository`：

- DeepSeek 请求使用真实 `StockDetail` 快照；
- AI 缓存 Key 继续包含股票代码和行情时间，新行情会产生新分析版本；
- 没有真实分时和日 K 时，Prompt 不传空数据冒充历史走势，并明确“仅基于当前行情快照”；
- 规则 Mock 分析同步移除“分时样本、日 K 趋势”等无数据依据的描述；
- 行情失败不发 AI 请求；
- AI 失败不影响真实行情展示；
- UI 必须分别展示“行情来源”和“AI 来源”，不能把真实行情等同于实时 AI 结论。

首页 AI Tab 暂时基于本次真实股票样本生成规则概览，并标记为规则解读；不为列表中的每只股票批量调用收费模型。

## 9. 测试

### 单元测试

- 单条和批量 GBK 解码后的文本解析；
- 沪市、深市、创业板、指数代码映射；
- 空正文、非预期前缀、字段不足、乱码、非法数字；
- 停牌/零价格、最高低于最低、时间缺失；
- 部分成功、全部失败、代码不匹配；
- 成交量和成交额单位转换；
- 远程成功、缓存命中、旧数据回滚保护；
- 首页/详情缓存隔离与共享；
- 快速切股和页面销毁后丢弃过期回调；
- 无分时/日 K 时图表和 AI 正常降级。

### 构建检查

```text
:shared:compileDebugKotlinAndroid --rerun-tasks
:shared:testDebugUnitTest
:androidApp:compileDebugKotlin
git diff --check
```

后续启用 iOS、鸿蒙目标时，再分别验证 `NetworkModule` 二进制请求和 GBK 解码，不在未验证前声明跨端真机通过。

### Android 真机验收

- 首页批量行情和三个指数；
- 详情字段与原始响应一致；
- 中文名称无乱码；
- 断网、超时、HTTP 异常、部分股票缺失；
- 缓存标记、手动重试、定时刷新；
- 快速切股、退出页面后无旧回调更新；
- 自选、持仓、模拟交易使用最新报价；
- 无真实时序数据时不展示假曲线；
- DevTools Network 面板可看到请求和返回。

## 11. 风险与约束

- `qt.gtimg.cn` 返回的是非 JSON、GBK 文本，解析规则必须由 Fixture 测试保护；
- 接口字段和可用性可能变化，所有字段位置集中维护，解析失败必须安全降级；
- 该接口未提供本期所需的完整分时/K 线能力，走势图必须单独接入真实时序数据；
- 市场开闭状态不能只靠工作日和本地时间准确判断法定节假日，首版仅作为展示提示；
- 不升级 Kotlin、Gradle、AGP、Kuikly，不新增网络依赖，不修改现有 DeepSeek Key 注入方式。
