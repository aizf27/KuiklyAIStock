# 个股 AI 分析模块实现方案计划

## 1. 目标与范围

将个股详情页现有的 AI 长文本区升级为：**结论 → 条件式观察计划 → 信号依据 → 风险边界**，突出 AI 分析与解读评分点。

- 本期只增强 `stock_detail`，不实现完整聊天页、不改交易流程。
- 使用 Mock 数据，明确标注“AI 分析演示”，不宣称已接入大模型。
- 不做雷达图、多维评分、AI 胜率或信心百分比，避免无依据数字和额外开发量。
- 后续真实 AI 服务通过 Repository 替换，本期不接入。

## 2. 页面设计

保留现有价格、指标、走势图顺序，替换其后的 AI 区域。默认展示结论、观察计划和风险；详细依据可点击展开。

| 模块 | 内容 | 展示方式 |
| --- | --- | --- |
| AI 综合判断 | 偏强 / 震荡 / 偏弱、一句话总结、适用周期 | 品牌浅色强调卡，结论最醒目 |
| 条件式观察计划 | 关注区间、确认条件、风险边界；参考目标可选 | 价位与说明分层展示，不只摆数字 |
| 信号解读 | 价格、成交量、技术形态等 2～3 条信号 | 状态标签 + 人话解释 + 对应依据 |
| 风险提醒 | 风险等级、主要风险、判断失效条件 | 文字与颜色共同表达，始终可见 |
| 分析信息 | 数据范围、样本时间、演示标识、免责声明 | 简短页脚，不混入系统当前时间 |
| 快捷追问 | 为什么这样判断？关注什么信号？主要风险是什么？ | 点击在当前区域展开对应解释 |

交互要求：

- 快捷追问复用已有结构化分析内容，标注预设解读；不需要假装实时生成。
- 不做只有日志、没有界面反馈的按钮，也不跳转尚未注册的 `stock_chat`。
- 分时 / 日 K 切换不自动改变分析周期，分析依据周期单独标明。
- 空分析显示“暂无 AI 解读”；行情仍正常显示。

## 3. 内容与数据规则

### 模型

保留 `AiAnalysis` 原有字段，避免破坏首页 AI 卡片等调用方；新增字段使用默认值：

- 趋势类型：枚举，偏强 / 震荡 / 偏弱。
- 风险等级、主要风险列表、失效条件。
- 可空的观察计划：关注区间、确认条件、可选确认价、可选参考目标、风险边界。
- 信号列表：标题、状态、解释、依据。

原有 `factSummary`、`trendJudgement`、`applicablePeriod`、`evidenceSummary`、`updatedAt`、`isDemo` 继续复用，不重复新增同义字段。

### Mock 生成

- 至少准备偏强、震荡、偏弱三类样本，内容不能仅替换股票名称。
- 数据构造放在 Repository 或独立 Mock 构造文件，UI 只负责展示。
- 点位、信号与详情页使用同一份样本；先核对 `StockChartMockData.kt` 与 Repository 走势是否一致。
- 有历史样本才能描述均线、前高、放量；不能仅凭当日涨跌编造这些信号。
- 无资金数据就不展示资金流入结论；数据不足时明确说明。
- 关注区间上下界有序、价位为正；无合理计划时显示“暂无明确观察计划”，不强行填满。
- 偏弱场景允许仅展示企稳观察条件和风险，不必配置上涨目标。
- 使用“若满足条件，则关注……”的表达，不承诺收益，不把观察计划直接绑定买卖按钮。

## 4. 最小改动范围

以下 Kotlin 文件均位于 `shared/src/commonMain/kotlin/com/example/kuiklyaistock/`：

| 文件 | 改动 |
| --- | --- |
| `model/StockModels.kt` | 扩展分析模型，增加必要的计划和信号结构 |
| `repository/StockRepository.kt` | 返回差异化、与行情一致的 Mock 分析 |
| `StockAiAnalysis.kt` | 拆分结论、计划、信号、风险小组件，接入展开交互 |
| `StockDetailPage.kt` | 传入内容宽度，维护展开状态及必要点击日志 |
| `StockDesignTokens.kt` | 仅补充缺失的语义 Token |

允许新增一个 Mock 分析构造文件，避免继续堆大 Repository；无需改宿主和依赖。同步增加 `shared/src/commonTest` 下相关测试。

## 5. 实施顺序

1. **核对现状**：阅读 `AGENTS.md`、`docs/TASKS.md` 和相关调用方；检查 `git status`。工作区已有大量未提交改动，必须基于现状增量修改，禁止恢复或覆盖。
2. **模型与数据**：增加结构化字段和三类样本，核对行情与图表依据，先补数据测试。
3. **核心 UI**：实现综合判断、观察计划、风险卡；保留原有事实和依据内容。
4. **解释交互**：实现信号列表、依据展开、三个快捷追问；股票切换或重新加载后避免残留上一只股票的解释状态。
5. **验证与记录**：检查调用方兼容性、编译和 diff；更新 `docs/TASKS.md` 实际完成项与待真机验证项。未经要求不提交。

## 6. 工程与验收

- 使用 Kuikly DSL、`observable`、`vif` / `velse`，不引入 Compose 或 Android 专有 API。
- 复用 `StockDesignTokens`：左右边距 16dp、卡片圆角 12dp、触控区域至少 44dp。
- 显式约束内容宽度；长说明换行，窄屏价位布局不溢出；风险和趋势都有文字标签。
- 复用现有 Bridge 日志，记录展开 / 追问等关键交互，不在渲染过程中重复打日志。
- 单测覆盖：三种趋势、区间合法性、缺失计划 / 信号、时间一致性、原有分析调用方兼容。
- UI 验证：三类样本、空分析、长文本、窄屏、追问展开、返回详情、现有收藏和模拟交易不受影响。
- 先确认现有 Gradle 任务，执行对应 Kotlin 编译及可运行测试；不能仅凭可能跳过的 metadata 任务认定通过。
- 执行 `git diff --check`。完整 APK 按需构建；编译或真机受环境限制时如实记录，不写“已通过”。

**完成标准：用户能快速读出当前判断、判断依据、下一步关注条件，以及什么情况会使判断失效。**
