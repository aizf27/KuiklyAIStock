# UI 统一问题与三页面优化方案

> 基于 `ui_image/` 中项目截图与同花顺截图整理。本文只记录设计判断与落地方案，暂不改代码，后续可直接转成 Figma 结构。

## 1. 截图对比结论

### 1.1 项目当前共性问题

1. **顶部导航栏侵入状态栏**
   - `StockTopBar` 当前固定高度 52，没有叠加 `pagerData.statusBarHeight`。
   - Android 宿主开启了沉浸式 `LAYOUT_FULLSCREEN`，因此页面内容会从摄像头/状态栏区域开始。
   - 真机刘海、挖孔和普通屏的安全距离都没有统一处理。

2. **卡片和列表宽度不稳定**
   - 截图中市场卡片右侧被截断，左右留白不对称。
   - 现有页面只给 `Scroller` 设置左右 padding，没有明确约束内容子节点为父容器宽度；在 Kuikly 不同渲染器上，子节点可能按内容宽度或测量宽度布局。
   - 行列表、卡片、详情面板没有统一的“内容轨道”规则，导致边缘对齐不一致。

3. **行情页与自选页只是换标题**
   - 两页复用同一套市场概览、表头和股票列表，缺少页面任务差异。
   - 行情页应该先帮助用户看市场状态，自选页应该先帮助用户看持仓/关注标的。
   - 当前自选页仍保留“全部行情”的结构，信息层级不符合用户预期。

4. **整体视觉与参考产品差距较大**
   - 项目偏“信息卡片 Demo”，同花顺偏“行情工作台”：顶部搜索、二级筛选、市场状态、指数摘要、资讯和排行层层展开。
   - 项目底部导航只有 3 项，暂不必照搬同花顺 6 项，但需要明确“行情 / 自选 / AI”三项的职责和选中态。

## 2. 统一问题修复方案

### 2.1 安全区：顶部和底部都纳入页面骨架

**推荐方案：共享页面壳统一处理，不在每个页面单独补间距。**

- 顶部栏总高度 = `statusBarHeight + 52dp`。
- 顶部容器背景覆盖状态栏，内部标题栏仍保持 52dp；标题、返回按钮只放在安全区下方。
- 直接复用项目已有 `TemplateNavigationBar` 的做法：读取 `pagerData.statusBarHeight`，不要写死 24dp 或 32dp。
- `StockTopBar` 的返回按钮继续保持至少 44dp 点击区域；标题在可用区域内真正居中，避免返回按钮导致标题偏移。
- 底部栏也预留系统手势/导航栏区域：内容高度 64dp，底部安全区单独追加 padding；列表滚动区域的 bottom padding 要大于底栏内容高度 + bottom inset。
- Android 宿主的沉浸式配置可以保留，但页面必须消费 inset；若后续 iOS/Web 接入，应由各宿主把安全区值传入同一页面壳。

**验收标准**

- 刘海/挖孔机上，标题和摄像头不重合。
- 普通屏、全面屏、底部手势导航三种设备上，顶部标题和底部 Tab 均不被遮挡。
- 页面滚动到最底部时，最后一行不被底部导航或手势条盖住。

### 2.2 内容轨道：所有页面统一左右边距和宽度

建立统一布局规则：

- 页面背景铺满屏幕；内容轨道左右固定 `16dp`，窄屏不再额外缩小。
- `Scroller`、列表容器和详情内容都显式占满父宽度；卡片、列表行、分割线均使用同一内容轨道，不依赖内容自适应宽度。
- 卡片采用 `width = parentWidth` 的等宽策略，不能在卡片内部再使用会撑宽父节点的固定宽度组合。
- 右侧价格列使用“最大可用宽度 + 文本右对齐”，名称列使用剩余空间；长名称、长数值要截断或缩小字号，不能把卡片撑出屏幕。
- 卡片统一圆角 12dp、内边距 16dp；列表行不要再套一层不对齐的卡片，使用整宽白底 + 1dp 分割线。
- 表头、列表行和卡片左右边缘必须在同一条垂直基线上。

**重点排查位置**

- `StockHomePage.kt`：Scroller 和行情内容容器的宽度约束。
- `StockMarketSummary.kt`：市场概览卡片的等宽和内部三列布局。
- `StockUiComponents.kt`：股票行右侧固定 112dp 可能在窄屏挤压名称列，需要改为可收缩布局。
- `StockDetailPage.kt`：价格卡片、指标卡片、走势图卡片沿用同一内容轨道。

**验收标准**

- 左右留白相等，卡片右边不截断。
- 360dp、375dp、412dp 宽度下均能完整显示价格、涨跌幅和操作按钮。
- 所有页面的卡片、表头、列表行左边缘对齐。

### 2.3 页面骨架：行情页和自选页分离职责

建议统一为以下骨架：

```text
安全区顶部栏
页面滚动内容
底部主导航 + 底部安全区
```

行情页和自选页共用颜色、字号、卡片、股票行组件，但不共用完整页面结构。通过“页面状态 + 页面专属模块”区分，而不是只修改标题。

## 3. 三个页面的优化方案

## 3.1 行情首页：先看市场，再看个股

### 页面结构

1. **顶部搜索框**
   - 放在顶部标题区域下方或替换普通标题栏中的标题位置。
   - 占据主要宽度，左侧搜索图标，placeholder：`搜索股票 / 指数 / 代码`。
   - 点击后可先复用详情页跳转；搜索能力未实现前展示不可编辑或 Mock 搜索入口。

2. **第一层市场切换**
   - 横向滚动：`A股`、`港股`、`美股`。
   - 默认选中 `A股`；港股、美股先展示空状态，保留后续数据接入位置。
   - 选中态使用品牌色文字 + 短下划线，不使用大面积按钮块。

3. **第二层内容切换**
   - `大盘`、`板块`、`个股`。
   - 默认 `大盘`；板块、个股暂展示空状态和轻量说明。

4. **市场状态核心卡片**
   - 仿照 `行情首页核心卡片.jpg`：左侧状态图标和状态文案，右侧资金净流入/关键指标。
   - 下方说明数据时间，例如：`以下为上一个交易日数据 · 2026-09-09 15:00`。
   - 状态根据系统时间变化：
     - 交易前：`未开盘`
     - 09:15–09:29：`集合竞价`
     - 09:30–11:30、13:00–14:44：`交易中`
     - 14:45–15:00：`即将收盘`
     - 15:00 后：`已收盘`
   - 第一版只按系统时间判断，并明确标注“演示数据”；节假日交易日历留给后续真实数据接入。

5. **三大指数小卡片**
   - `上证指数`、`深证成指`、`创业板` 三列等宽。
   - 展示点位、涨跌额、涨跌幅；上涨使用红色，下跌使用绿色，沿用项目现有颜色语义。
   - 卡片背景使用极浅红/绿底，不使用高饱和大色块。

6. **涨跌对比条**
   - 左侧显示 `跌 N`，右侧显示 `涨 N`，中间为按数量比例绘制的双色进度条。
   - 增加“上一交易日总成交额”或“市场热度”说明。
   - 进度条必须与三大指数卡片同宽，避免独立左右边距。

7. **盘前/盘中/盘后信息卡**
   - 根据时间切换四类标题：`盘前必读`、`午盘点评`、`收盘点评`、`晚间复盘`。
   - 第一版只放 1 张卡片，展示标题、日期、1 行摘要和右箭头；不堆叠复杂资讯列表。

8. **股票排行 Mock 区**
   - 放在资讯卡片下方，先做一个排行模块即可：`涨幅榜` / `跌幅榜` 二选一或横向切换。
   - 复用股票行组件，保留名称、代码、最新价、涨跌幅和收藏入口。

### 行情页与当前版本的主要变化

- 从“标题 + 市场概览卡 + 全部股票列表”改为“搜索 + 两层筛选 + 市场状态 + 指数 + 涨跌对比 + 时效资讯 + 排行”。
- `A股 / 大盘` 是默认可用组合；其余组合先留空，不伪造数据。
- 现有市场概览卡可拆成“核心状态卡 + 指数卡 + 涨跌对比”三个组件，便于后续 Figma 和代码复用。

## 3.2 自选页：突出关注列表，不重复行情首页

### 页面结构

1. **顶部栏**
   - 标题：`自选`，右侧提供编辑/排序入口。
   - 可保留一个紧凑的市场摘要条，例如 `上证 3280.12 +0.42%`，但不再放完整市场概览大卡。

2. **自选分组/筛选**
   - 第一版提供：`自选股`、`指数` 两个分组；如果暂不做分组，至少保留 `自选股` 标题和股票数量。
   - 后续可扩展自定义分组，但当前不增加复杂交互。

3. **列表表头**
   - `名称 / 代码`、`最新价`、`涨跌`、`涨跌幅`。
   - 参考同花顺自选页的密集表格，但控制字号和列间距，保证 360dp 宽度可读。

4. **自选列表**
   - 每行支持点击进入 `stock_detail`，左滑/编辑态移除收藏暂不做。
   - 收藏星标改为明确的实心/空心状态；状态色不要使用过深棕色，建议使用品牌色或中性金色。
   - 行高建议 64–72dp，重要数字右对齐。

5. **空状态**
   - 无自选时显示：插图/星标 + `还没有关注股票` + `去行情添加`。
   - 不显示完整市场概览卡，避免“自选为空但页面像行情页”。

### 与同花顺自选页的取舍

- 保留：指数摘要、表格列、编辑/排序意识、添加股票入口。
- 暂不做：持仓、交易、资讯、资产、复杂分组和底部 6 项导航。
- 项目核心仍是“AI 股票 Demo”，自选页的入口价值是快速回到详情和 AI 解读，而不是复制券商工作台。

## 3.3 个股详情页：先解决核心走势图，再补信息密度

### 页面结构

1. **顶部栏**
   - 返回、股票名称、收藏；标题栏消费安全区。
   - 名称下方显示代码、市场、数据时间和“演示数据”。

2. **实时价格区**
   - 左侧突出最新价；右侧显示涨跌额和涨跌幅。
   - 可补充今开、最高、最低、成交额等关键指标，但不要在首屏铺满同花顺式几十个字段。

3. **走势图区（核心）**
   - 第一版保留 `分时`、`日K` 两个周期，增加 `周K`、`月K` 作为后续扩展位。
   - 图表卡片内部必须有：当前价、昨收基准线、高/低、时间轴、涨跌颜色。
   - 走势图宽度使用内容轨道的实际可用宽度，不能传入固定屏幕宽度；避免 Canvas 右侧溢出。
   - 分时图建议采用“主图 + 成交量”上下结构；日K 再增加均线和成交量，不要一开始实现盘口、逐笔明细等复杂区域。
   - 图表交互优先级：周期切换 > 横向/纵向读数 > 十字光标。第一版只做周期切换和静态 Mock 数据即可。

4. **关键行情指标**
   - 使用 2 列网格：今开/昨收、最高/最低、成交量/成交额。
   - 卡片内容和走势图卡片统一圆角、内边距、分割线。

5. **AI 观点卡片**
   - 放在走势图之后，标题明确：`AI 观点参考`。
   - 内容分为“趋势摘要、风险提示、关注指标”三行，先使用 Mock 文案。
   - 追加免责声明：`仅供信息参考，不构成投资建议`。

### 走势图的分阶段实现

- **阶段 1：** 修正当前 Canvas 尺寸、内边距、基准线和空数据状态，保证不裁切、不溢出。
- **阶段 2：** 增加分时图成交量、网格线、价格标签和统一的涨跌色。
- **阶段 3：** 增加日K/周K/月K、均线和手势读数。
- **暂不复制：** 同花顺右侧盘口、逐笔成交、下单栏、复杂指标面板；这些会显著增加跨端实现成本，也偏离当前 Demo 目标。

## 4. 建议先落地的优先级

### P0：先修统一问题

1. 顶部 status bar 安全区。
2. 底部 navigation bar 安全区和滚动底部留白。
3. 内容轨道宽度、卡片左右边距、右侧裁切。
4. 行情页和自选页结构拆分。

### P1：行情首页改版

1. 搜索框。
2. `A股 / 港股 / 美股`。
3. `大盘 / 板块 / 个股`。
4. 市场状态核心卡 + 三大指数 + 涨跌对比。
5. 时效资讯卡 + Mock 排行。

### P2：自选页改版

1. 紧凑市场摘要。
2. 自选列表表头和排序入口。
3. 空状态和添加股票入口。

### P3：个股详情页升级

1. 走势图不裁切。
2. 分时/日K视觉层级。
3. 成交量和网格线。
4. AI 观点卡片。

## 5. Figma 预留规范

- **画布基准：** 375 × 812，另做 360 × 800 和 412 × 915 检查响应式。
- **安全区：** 顶部按真实设备 inset 标注，底部按手势条 inset 标注；安全区不计入内容模块高度。
- **内容边距：** 16dp；卡片内边距 16dp；列表行左右 16dp。
- **圆角：** 大卡片 12dp，轻量标签/按钮 8dp。
- **间距：** 8dp 基础间距，模块间 16dp，页面大区块 24dp。
- **字体层级：** 页面标题 24、模块标题 18、正文 16、辅助信息 12–13、行情数字 24–32。
- **颜色：** 页面背景浅灰；卡片白色；上涨红、下跌绿；品牌蓝只用于选中态、操作和 AI 强调，不大面积铺色。
- **组件命名建议：** `SafeAreaShell`、`StockTopBar`、`MarketSegmentTabs`、`MarketStatusCard`、`IndexMiniCard`、`AdvanceDeclineBar`、`TimedInsightCard`、`WatchlistTable`、`StockTrendCard`、`AiOpinionCard`。

## 6. 本轮结论

先不要直接照搬同花顺的全部功能。第一轮应优先修复安全区、宽度和页面职责这三个基础问题，再把行情首页做成“市场驾驶舱”，把自选页做成“关注列表”，把个股页做成“价格 + 走势图 + AI 观点”的详情页。这样既能接近参考产品的信息层级，也能保持 Kuikly 跨端 Demo 的实现边界。
