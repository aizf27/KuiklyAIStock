# 个股详情 AI 精简与真实模型接入计划

> 状态：待用户审核，审核通过并确认模型接入参数后再实施。
> 日期：2026-09-11。

## 1. 目标

在保留现有结构化 `AiAnalysis` 和 Mock 降级能力的基础上：

1. 缩短详情页 AI 区域的默认篇幅，让用户先看到结论、观察条件和核心风险。
2. 接入真实模型生成结构化分析，但不让模型编造行情数据或直接给出买卖承诺。
3. AI 请求失败、超时或返回格式异常时，不影响行情、收藏和模拟交易流程。
4. 明确区分“行情数据来源”和“AI 内容来源”。当前行情仍是 Mock 时，不宣传为实时行情分析。

## 2. 精简后的 UI

### 2.1 默认态

默认只展示一张紧凑主卡和快捷追问：

```text
AI 分析                         [AI 生成/演示]
┌──────────────────────────────┐
│ [偏强] 适用周期：短线         │
│ 一句话综合判断，最多 2～3 行   │
│                              │
│ 观察：若满足条件，则关注 XX   │
│ 风险：核心风险一句话          │
│                              │
│ 查看完整分析                  │
└──────────────────────────────┘
[为什么这样判断] [关注信号] [主要风险]
```

默认态规则：

- 合并现有“综合判断”和“观察计划”，不再连续展示多张大卡。
- 综合判断最多展示 2～3 行。
- 观察计划默认只展示关注区间和确认条件；确认价、参考目标放入完整分析。
- 风险默认只展示最高优先级的一条。
- 无观察计划时显示“暂无明确观察计划”，不占用额外卡片。
- 页面默认高度目标控制在约 260～360dp，具体以窄屏不溢出为准。

### 2.2 完整分析展开态

点击“查看完整分析”后，在当前区域追加：

1. 事实摘要；
2. 完整观察计划；
3. 2～3 条信号摘要；
4. 点击信号后展开数据依据；
5. 风险等级、主要风险和判断失效条件；
6. 数据范围、行情时间、AI 生成时间和免责声明。

再次点击可收起。股票切换、重新加载或加载失败时恢复默认收起状态。

### 2.3 快捷追问

保留三个入口：

- 为什么这样判断？
- 关注什么信号？
- 主要风险是什么？

调整行为：

- 同一时间只显示一个回答面板，切换问题时替换内容，避免三个答案累计拉长页面。
- 真实模型分析已成功时，优先从本次结构化结果组合答案，不为每次点击再次请求模型。
- Mock 或缓存结果下标记“预设解读”；真实模型结果下标记“基于本次分析”。
- 点击继续调用 `BridgeModule.log(...)`，但不记录 Key、完整 Prompt 或敏感响应。

## 3. 真实模型接入方案

### 3.1 推荐链路

```text
Kuikly 共享页面
    → AiAnalysisRepository
    → Android Bridge HTTP 请求
    → AI 代理服务
    → 模型厂商 API
```

推荐使用代理服务，原因是模型 Key 放入 APK 后可被提取。Key 只保存在代理服务环境变量中，客户端只保存代理地址。

若本次仅用于个人真机临时验证，也可以采用“Android 直接请求模型”的调试方案，但必须明确接受以下限制：

- Key 最终会进入 APK，不能视为安全存储；
- 只能使用低额度、可随时吊销的测试 Key；
- Key 只从未提交的 `local.properties` 或环境变量读取；
- 禁止写入 Kotlin、Markdown、Git 历史和日志；
- 正式发布前必须改为代理服务。

审核时需要在“代理服务方案”和“仅本地调试直连方案”之间确认一个。本计划默认按代理服务实施。

### 3.2 工程分层

新增统一接口，页面不直接处理 HTTP 和模型协议：

```text
AiAnalysisRepository
├── MockAiAnalysisRepository      现有规则分析和失败降级
└── RemoteAiAnalysisRepository    真实模型结果
```

职责划分：

- 共享层：构造行情请求数据、维护加载状态、解析统一结果、做业务校验。
- Android Bridge：执行网络请求、设置超时、返回状态码和响应 JSON。
- 代理服务：持有 Key、拼装模型请求、约束输出格式、限流和隐藏厂商错误细节。
- UI：只展示 `AiAnalysis`，不拼 Prompt、不解析厂商原始文本。

当前 `commonMain` 没有通用网络依赖，为避免升级构建工具或新增跨端依赖，本次优先复用现有 `BridgeModule`，在 Android 宿主实现异步 HTTP 请求。

## 4. 请求与返回数据

### 4.1 发送给模型的数据

只发送当前仓库已经具备的结构化行情：

- 股票名称、代码；
- 当前价、涨跌额、涨跌幅；
- 开盘、昨收、最高、最低；
- 成交量、成交额；
- 分时点列；
- 日 K Mock 点列；
- 行情数据时间。

不发送用户持仓、交易记录、收藏列表、设备信息和任何 Key。

### 4.2 返回结构

继续复用现有 `AiAnalysis`：

- `trendType`：`STRONG / SIDEWAYS / WEAK`；
- `trendJudgement`；
- `factSummary`；
- `applicablePeriod`；
- `observationPlan`；
- `signals`；
- `riskLevel`；
- `majorRisks`；
- `invalidCondition`；
- `updatedAt`；
- `isDemo`。

建议补充带默认值的来源字段：

- `source`：`MOCK / REMOTE / CACHE`；
- `modelName`：可空；
- `generatedAt`：AI 生成时间；
- `requestId`：可空，仅用于排查问题。

行情时间与 AI 生成时间分开显示，禁止用 AI 生成时间冒充行情时间。

### 4.3 输出约束

模型提示词和本地校验共同保证：

- 只引用请求中存在的数据；
- 缺少均线、资金流、历史成交量时明确说明数据不足，不允许猜测；
- 不输出“必涨”“稳赚”“建议立即买入”等承诺；
- 观察区间必须为正数且上界不小于下界；
- 最多 3 条信号、2 条主要风险；
- 偏弱样本允许没有参考目标；
- 返回 JSON，不返回 Markdown 长文；
- `trendJudgement`、信号解释等设置长度上限，避免 UI 再次变成长文章。

## 5. 加载、缓存与降级

详情页加载流程：

1. 先显示行情和本地 Mock/缓存分析，避免页面等待模型才可用；
2. 后台请求真实模型；
3. 成功且校验通过后替换 AI 区域；
4. 请求失败时保留旧结果，并显示轻量提示“AI 更新失败，当前展示缓存/演示分析”；
5. 用户可点击“重新分析”，同一股票请求进行中时禁止重复提交。

建议策略：

- 连接超时 10 秒，读取超时 20 秒；
- 仅对网络瞬时错误重试 1 次，不重试鉴权和格式错误；
- 按“股票代码 + 行情时间 + 模型版本”缓存结果；
- 相同行情时间不重复消耗模型额度；
- 缓存仅保存结构化结果，不保存 Key 和完整厂商响应；
- 旧请求返回时校验股票代码，避免覆盖用户刚切换的新股票。

## 6. 页面状态

在 `StockDetailPage.kt` 增加或调整：

- `isAiDetailExpanded`：完整分析是否展开；
- `aiLoadState`：`IDLE / LOADING / SUCCESS / FAILURE`；
- `selectedAiQuickQuestion`：当前快捷追问；
- `expandedAiSignalIndex`：当前信号依据；
- `displayedAnalysis`：Mock、缓存或远程分析；
- 当前请求股票代码或请求序号，用于丢弃过期回调。

状态清理规则：

- 股票切换、重新加载、加载失败时清空展开状态和快捷追问；
- 图表分时/日 K 切换不触发 AI 请求；
- AI 失败不清空行情详情；
- 页面销毁后不再写入已失效页面状态。

## 8. 测试

### 单元测试

覆盖：

- 远程 JSON 正常解析成 `AiAnalysis`；
- 未知枚举、字段缺失、非法价格区间被拒绝或安全降级；
- 可选确认价、参考目标、观察计划为空时正常；
- 超时、鉴权失败、限流、服务端错误和非 JSON 返回；
- 旧股票请求不能覆盖新股票；
- 相同行情时间命中缓存，不重复请求；
- 远程失败后行情详情和 Mock 分析仍可用；
- 旧 `AiAnalysis` 构造调用继续兼容；
- 默认态、展开态和快捷追问的状态切换逻辑。

### 编译检查

实施后执行：

```text
:shared:compileDebugKotlinAndroid --rerun-tasks
:shared:testDebugUnitTest
:androidApp:compileDebugKotlin
git diff --check
```

完整 APK 若仍触发现有 AGP 7.4.2 与 Kotlin 2.1.21 的 D8 兼容问题，只记录环境限制，不升级依赖掩盖问题。

### 真机验收

由用户检查：

- 默认 AI 区域是否明显缩短；
- 窄屏是否换行且不横向溢出；
- 展开/收起、信号依据和快捷追问是否正确；
- 加载、失败、重试和缓存提示是否清晰；
- 弱网或关闭代理时行情、收藏和交易是否仍正常；
- 返回栈和股票切换是否残留上一只股票的分析。

## 9. 实施顺序

1. 精简现有 Mock UI，并完成展开/收起状态。
2. 抽象 `AiAnalysisRepository`，保持 Mock 实现可独立工作。
3. 增加 Bridge 网络能力和远程返回解析校验。
4. 接入代理服务或经确认的本地调试直连方式。
5. 增加缓存、失败降级、重试和过期请求保护。
6. 补充测试、编译检查和 `docs/TASKS.md` 实际结果。
7. 用户真机验收，不在未验证前写“真机已通过”。

## 10. 审核后需要确认的信息

实施真实模型前需要用户提供或确认：

1. 模型厂商；
2. API Base URL；
3. 模型名称；
4. 是否兼容 OpenAI Chat Completions 或 Responses 协议；
5. 选择代理服务方案，还是接受风险的本地调试直连方案；
6. 若使用代理服务，代理部署地址或是否由本仓库提供最小本地代理；
7. 测试 Key 的注入方式。Key 不写入聊天记录、源码、Markdown 或 Git。

## 11. 明确不做

- 不把真实模型接入描述为真实行情接入；
- 不增加 AI 胜率、信心百分比和收益承诺；
- 不让快捷追问每次都产生新的计费请求；
- 不实现通用聊天页；
- 不修改收藏、持仓和模拟交易业务；
- 不升级构建工具和核心依赖；
- 未经明确要求不提交 Git。
