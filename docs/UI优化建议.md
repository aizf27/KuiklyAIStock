# KuiklyAIStock UI 优化建议

## 1. 结论

当前版本已具备“行情 -> 详情 -> AI 解读”的可演示闭环，但整体仍接近技术 Demo：大面积白色圆角卡片、偏松的列表密度、泛化的蓝色强调色，以及不足以支撑行情判断的市场层级。目标不应是把页面堆得更满，而是把它升级为一款能让用户快速完成“看大盘、找标的、判断异动、阅读 AI 观点”的正式行情 App。

本建议参考同花顺、东方财富等成熟股票客户端常见的产品组织方式：先给出市场全貌，再提供高密度标的扫描，最后以可验证的数据承接详情和观点。不会复制其交易、开户、社区等重功能。

## 2. 当前界面审计

| 区域 | 当前表现 | 主要问题 | 优化方向 |
| --- | --- | --- | --- |
| 全局视觉 | 浅灰背景、白色卡片、蓝色选中态 | 风格接近通用 SaaS，缺少金融行情的紧凑与实时感 | 建立行情专用的颜色、字号、间距和状态语义 |
| 首页顶部 | 导航栏“AI 股票行情”后又出现“行情中心” | 标题语义重复，占用了首屏有效高度 | 保留一个顶部标题，将次级区域改为可操作的搜索与市场切换 |
| 市场概览 | 仅展示股票总数、上涨数、下跌数 | 不能回答市场强弱、资金活跃度和主线方向 | 增加核心指数、涨跌家数、成交额、涨停/跌停等摘要位 |
| 行情列表 | 每行是留白较多的独立卡片，名称、价格、涨跌幅为主 | 同屏可见标的太少；趋势箭头的信息价值低 | 改为高密度分隔列表，并用微型分时线或量价状态代替箭头 |
| 首页导航 | “行情 / 自选 / AI解读”三个一级 Tab | “AI 解读”既像内容页也像工具入口，当前与首页的关系不够清晰 | 近期保留三 Tab；正式版扩展为“行情 / 自选 / AI / 我的”，搜索作为全局入口 |
| 股票详情 | 价格、简化走势、四个基础指标、AI 文本纵向排布 | 缺少周期切换、昨收/今开、成交强度等判断基准；图表不可交互 | 重组为价格头部、周期与图表、关键指标、AI 观点四层 |
| AI 解读 | 蓝色卡片内展示结论、风险提示和更新时间 | 观点与事实数据混排，可信度和时效性不足，容易被理解为投资建议 | 明确“数据事实 / AI 推断 / 风险提示”，增加数据时间、适用周期和置信度 |
| 状态与反馈 | 有文字加载、空态和错误态 | 缺少骨架屏、刷新反馈、市场闭市标识和数据延迟提示 | 增加可感知的实时状态，不让用户把 Mock 或旧行情当成实时数据 |

审计依据：`StockHomePage.kt`、`StockDetailPage.kt`、`StockAiPage.kt`、`StockUiComponents.kt`、`StockMarketSummary.kt` 与 `StockTrendChart.kt` 的现有布局和组件实现。

## 3. 正式 App 的信息架构

```text
行情
  市场概览 -> 指数 / 热门板块 / 异动榜 / 全部行情
  搜索 -> 股票、指数、板块
自选
  自选分组 -> 自选列表 -> 股票详情
AI
  今日市场观点 -> 个股解读 -> 对话问答（Task 2）
我的
  账号与偏好 -> 提醒 -> 数据与隐私说明

股票详情
  报价头部 -> 分时/K线 -> 关键行情 -> AI 解读 -> 资讯与公告
```

初版不能支持的页面入口应显示为“即将开放”或不展示，不能做无响应的占位入口。Task 2 完成前，AI 页只保留“市场解读”和“重点股票”，问答能力完成后再加入“问问 AI”作为主操作。

## 4. 视觉系统建议

### 4.1 颜色

- 背景：使用接近白色的 `#F6F7F9`，降低现有冷灰蓝的后台感。
- 容器：以白底加细分隔线为主，减少每一个区块都做浮层卡片的效果。
- 上涨：`#E64545`，下跌：`#1A9B62`，平盘：`#667085`。颜色必须全局固定。
- 选中和可操作元素：使用一个克制的品牌蓝，例如 `#246BFD`；不使用蓝色表达行情涨跌。
- 风险：使用琥珀色与清晰的图标/标签，不只依赖文字或颜色区分。
- 深色模式：在设计 Token 层预留，不在当前 Task 中局部硬编码深色样式。

### 4.2 字体与数字

- 股票名称采用 16sp 半粗，代码采用 11-12sp 常规；价格采用 20-24sp 数字优先的粗体。
- 涨跌额和涨跌幅使用等宽数字或固定宽度右对齐，列表扫描时价格列不会跳动。
- 页面标题控制在 20sp 左右，避免首页“行情中心”和详情页名称竞争首屏主信息。
- 标题、正文、辅助说明分别最多使用三档字重；避免所有关键信息都加粗。

### 4.3 间距与容器

- 页面左右安全边距保持 16dp；普通列表行高度控制在 64-72dp，详情模块间距 20-24dp。
- 列表使用 1dp 分隔线或弱分组背景，市场概览、AI 摘要等真正聚合的信息才用 8dp 圆角卡片。
- 底部导航顶部加入细分隔线，选中态以图标和文字颜色为主，避免整块浅蓝背景抢夺内容注意力。

## 5. 页面改造建议

### 5.1 行情首页

首屏优先展示市场，而不是重复标题。建议顺序如下：

```text
AI 股票                       [搜索] [消息/提醒]
沪深 / 港股 / 美股             市场状态：已收盘 15:00
上证指数  3,280.12  +0.42%     深证成指  10,456.20  -0.18%
上涨 3120   下跌 1840   成交额 1.26 万亿
自选 | 热门 | 涨幅榜 | 跌幅榜 | 异动
名称 / 代码                  最新 / 涨跌幅 / 微型走势
腾讯控股 00700               382.40 +1.81%  ─╮╭─
```

- 用横向市场分段控件替换单一“盘中行情”文案，为 A 股、港股、美股的后续扩展留下位置。
- 市场概览首期至少接入两个核心指数和涨跌家数；数据未接入时明确显示“演示数据”，不要伪装实时行情。
- 列表列头支持“最新价 / 涨跌幅”排序状态，排序图标只在当前列显示。
- 星标点击区独立，整行点击区清楚；两者均不小于 44dp。
- 为每只股票保留可选的微型趋势线；若暂无真实走势，不显示装饰性的方向箭头。
- 搜索入口应在首页首屏可见，并能够搜索股票代码、名称和指数。即使第一阶段只匹配 Mock 数据，也应完成交互状态。

### 5.2 自选页

- 增加“编辑”模式，支持拖拽排序、批量移除和分组名称；初版可先完成排序和移除。
- 空态不只写“暂无自选股票”，提供“去行情添加”的明确按钮。
- 显示每只自选的价格提醒、异动状态或 AI 关注标签，避免自选页与行情列表完全重复。

### 5.3 股票详情页

建议将首屏设计为价格决策区，基础数据与 AI 观点按语义分层：

```text
[返回] 腾讯控股 00700                         [自选] [分享]
382.40                 +6.80  +1.81%          已收盘 15:00
今开 375.60  昨收 375.60  最高 386.20  最低 374.60
分时 | 日K | 周K | 月K                    [全屏]
              可缩放、带基准线与十字提示的图表
成交量  成交额  换手率  市盈率             更多 >
AI 观点  偏多 / 置信度中 / 适用周期 1-5 日
事实数据：...   推断：...   风险：...
```

- 价格区加入昨收、今开，并在可获得数据后增加换手率、市盈率；不能提供的数据不显示，不要用 `--` 填满。
- 图表应提供“分时 / 日 K / 周 K / 月 K”周期切换，首期可先实现分时和日 K 两个静态数据集。
- 图表需要昨收基准线、最高/最低标记、当前点价格；第二阶段再加入手势缩放、十字光标和全屏。
- 指标区由当前横向四项改为 2 列网格，避免窄屏下 50dp 固定宽度造成拥挤。
- 收藏按钮保留；新增分享入口只在具备真实分享能力后显示。
- 资讯、公告、财务、资金流向属于正式版重要模块，但应等待数据源明确后开发，不能以空卡片提前占位。

### 5.4 AI 解读页与详情 AI 区

- 视觉上将“市场事实”和“AI 观点”分开：事实区域使用常规信息样式，AI 区使用轻量品牌色边框或标签，不使用整张大面积浅蓝卡片。
- 每条 AI 观点固定展示：结论标签、适用周期、生成时间、信心等级、依据摘要、风险提示。
- 将“操作提示”改为“关注要点”或“观点参考”，避免暗示确定性买卖建议。
- 用户应能展开“依据数据”，看到涨跌、成交量、趋势等原始字段，提升可解释性。
- AI 页面顶部加入一键“问问 AI”主操作，Task 2 的 `stock_chat` 完成后承接到真实对话页。
- 对 Mock 内容加“演示数据”标识，正式接入后改为“数据截至 HH:mm，AI 生成于 HH:mm”。

## 6. 关键交互与可信度

1. 刷新：首页下拉刷新，顶部显示最近更新时间和加载中状态；失败时保留上一次数据并提示“数据更新失败”。
2. 闭市：在标题区显示“交易中 / 午间休市 / 已收盘 / 非交易日”，任何价格旁边都保留时间。
3. 搜索：支持输入代码、名称、拼音首字母；历史记录和热门搜索后续再加。
4. 提醒：正式版应有价格/涨跌幅提醒入口，未实现前不展示通知图标。
5. 风险：AI 结论、延迟行情和 Mock 数据均必须有明确边界说明；风险提示不能放在长页面底部才出现。
6. 无障碍：上涨、下跌除了颜色，还要保留正负号和文字；交互控件具备不小于 44dp 的命中区域。

## 7. 实施优先级

### P0：先让现有 Demo 像正式行情产品

1. 建立颜色、字号、间距、分隔线、圆角和数字对齐的统一 Token。
2. 删除首页重复标题，增加市场状态、搜索入口和“演示数据”标识。
3. 重做市场概览为指数 + 涨跌家数 + 成交额的紧凑区块。
4. 将 `StockQuoteRow` 改为高密度分隔列表，去除低价值趋势箭头，完善列对齐。
5. 重排详情页价格头部、指标网格和图表的首屏优先级。
6. 将 AI 的操作性措辞、生成时间、风险和数据依据标准化。

### P1：补足正式 App 的核心体验

1. 完成 Task 2 的 AI 问答，并将其作为 AI 页的主操作。
2. 完成搜索、自选排序、行情分类和刷新反馈。
3. 完成分时/日 K 切换、昨收基准线和图表详情信息。
4. 增加价格提醒和消息中心的产品入口，数据能力未就绪时不显示。

### P2：数据与产品能力到位后再做

1. 资讯、公告、板块、资金流和财务数据。
2. 自选分组、跨设备同步、账号体系和个性化推荐。
3. 深色模式、横屏图表和高级图表交互。

## 8. 建议验收标准

- 360x800 的首屏可同时看到市场状态、两个指数、涨跌家数和至少 3 只股票。
- 行情列表各行的代码、价格、涨跌额、涨跌幅对齐稳定，长名称不遮挡数值。
- 用户可在两步以内完成搜索、添加自选、进入详情和发起 AI 问答。
- 每个价格和 AI 结论都能看见时间或数据属性；Mock、延迟、失败状态均不被伪装成实时结果。
- 上涨、下跌、风险、收藏、可点击区域不只通过颜色表达。
- P0 完成后，首页、详情、AI 页不再有重复大标题、无意义卡片或空白占位入口。

## 9. 推荐改造顺序

先做 P0 的视觉 Token 与首页，再改列表和详情首屏，最后统一 AI 模块。这样能复用 `StockUiComponents.kt` 的共享能力，避免首页、详情和 AI 页各自形成一套风格；Task 2 完成后再接入搜索和问答的完整闭环。
